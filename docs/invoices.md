# Invoices

This document mirrors the official efacturapty API reference (Stoplight docs shipped as PDFs
alongside this gem) rather than a simplified/example schema. Every field name, required flag,
and constraint below comes directly from that reference.

## Creating an invoice

```ruby
client.invoices.create(payload, include_qr: false, include_xml: false, locale: "es-PA")
```

- `payload` is a plain Ruby Hash forwarded as-is to `POST /api/v1/Invoices` — the gem does not
  build or reshape the DGI structure for you, so any key you omit or misspell simply won't reach
  the API in the expected shape. See "Client-side validation" below for the pre-flight checks
  that do run before the request is sent.
- `include_qr` → sends `?qr=true`, includes `qrContentImageBase64` in the response.
- `include_xml` → sends `?xml=true`, includes the authorized `xml` in the response.
- `locale` sets `Accept-Language` (**required** by the API; official default is `es-PA`, not `es`).
- The gem sends `Content-Type: application/json-patch+json`, matching the API's documented
  content type for this endpoint.

### Client-side validation

Emitting an invoice is a slow, side-effecting call to a PAC — a bad request wastes a round-trip
and comes back as an opaque HTTP 400/422. `create` (and the credit/debit note helpers, which all
delegate to it) run `Efacturapty::InvoiceValidator` against the payload **before** making any HTTP
request, and raise `Efacturapty::ValidationError` if it fails.

The validator is deliberately **permissive, not authoritative** — it only rejects what the
official docs make unambiguous and that the API cannot default on your behalf: presence of
`datosGenerales`, `informacionReceptor`, a non-empty `listaItems`, `totales`; closed enums
(`tipoEmision`, `tipoDocumento`, `naturalezaOperacion`, `tipoOperacion`, `destinoOperacion`,
`tipoTransaccionVenta`, `tipoSucursal`, ITBMS rates, `tiempoPago`); `puntoFacturacion` matching
`^\d{3}$` and not `"000"`; item bounds (`numeroSecuenciaItem` 1–9999, `descripcionProductoServicio`
2–500 chars); and documented conditionals (`facturaExportacion` required when `destinoOperacion`
is 2; `documentosFiscalesReferenciados` required for `tipoDocumento` 04/05;
`grupoInformacionPago` required when `tiempoPago` is 2 or 3). Fields the API can default
(`numeroDocumento`, `fechaEmision`, `puntoFacturacion`'s own default, computed totals, etc.) are
never required here even where the reference docs show a "required" badge. Everything else
(cross-field math, ITBMS calculation, business rules) is left entirely to the API to enforce.

```ruby
begin
  client.invoices.create(payload)
rescue Efacturapty::ValidationError => e
  e.errors   # => ["listaItems is required and must be a non-empty array", ...]
  e.message  # => "Invoice payload is invalid: listaItems is required and must be a non-empty array; ..."
end
```

To bypass validation for a single call, pass `validate: false`:

```ruby
client.invoices.create(payload, validate: false)
```

To disable it globally:

```ruby
Efacturapty.configure { |c| c.validate_invoices = false }
```

`config.validate_invoices` defaults to `true`. See [`docs/configuration.md`](configuration.md).

### Top-level InvoiceRequest keys

| Key | Type | Required | Description |
|-----|------|----------|--------------|
| `datosGenerales` | Object | Yes | General invoice data |
| `listaItems` | Array of Objects | Yes | Line items |
| `totales` | Object | Yes | Invoice totals |

### `datosGenerales`

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `tipoEmision` | string | Yes | `01` Autorización de Uso Previa, `02` operación en contingencia. Default `01`. |
| `tipoDocumento` | string | Yes | `01` Factura de Operación Interna, `02` Importación, `03` Exportación, `04` Nota de Crédito referente a una o varias FE, `05` Nota de Débito referente a una o varias FE, `06` Nota de Crédito genérica, `07` Nota de Débito genérica, `08` Factura de Zona Franca, `09` Reembolso, `10` Factura de operación extranjera. Default `01`. |
| `numeroDocumento` | string | Yes | Sequential document number per taxpayer. Auto-generated by efacturapty.com if omitted. |
| `puntoFacturacion` | string | Yes | Exactly 3 digits, `^\d{3}$`, `000` not allowed. Default `001`. |
| `fechaEmision` | string (`date-time`) | Yes | **Exactly 25 characters**, e.g. `2022-05-17T14:23:00-05:00` (full ISO-8601 with UTC offset — not a bare `YYYY-MM-DD`). Defaults to the current date if omitted. |
| `fechaSalidaEstimada` | string (`date-time`) | No | Same 25-character format. Inform when known. |
| `naturalezaOperacion` | string | Yes | `01` Venta, `02` Exportación, `03` Re-exportación, `04` Venta de fuente extranjera, `05` Servicio de fuente extranjera, `10` Transferencia/Traspaso, `11` Devolución, `12` Consignación, `13` Remesa, `14` Entrega gratuita, `20` Compra, `21` Importación. Default `01`. |
| `tipoOperacion` | integer | Yes | `1` Salida o venta, `2` Entrada o compra (factura de compra para comercio informal). Default `1`. |
| `destinoOperacion` | integer | Yes | `1` Panamá, `2` Extranjero. Default `1`. |
| `tipoTransaccionVenta` | integer | No | Only when `tipoOperacion` is `1`: `1` Venta de Giro del negocio, `2` Venta Activo Fijo, `3` Venta de Bienes Raíces, `4` Prestación de Servicio. Default `1`. |
| `tipoSucursal` | integer | No | `1` Mayor cantidad de operaciones al detal (retail), `2` mayor cantidad al por mayor. Default `1`. |
| `informacionInteresEmisor` | string | No | Up to 5000 characters, e.g. "Gracias por su compra". |
| `informacionEmisor` | Object | No | Filled from the efacturapty account; usually not needed. |
| `informacionReceptor` | Object | Yes | Receiver data (RUC, name, address, location, país). |
| `facturaExportacion` | Object | Conditional | Required if `destinoOperacion` is `2` (Extranjero). |
| `documentosFiscalesReferenciados` | Array of Objects | Conditional | Required for Notas de Crédito/Débito that reference one or more FEs (`tipoDocumento` `04`/`05`). The gem's `create_credit_note`/`create_debit_note` helpers build this automatically. |

### `listaItems` — line item

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `numeroSecuenciaItem` | integer | Yes | Row number, 1–9999. |
| `descripcionProductoServicio` | string | Yes | 2–500 characters. |
| `codigoInternoItem` | string | No | Internal product/service catalog code. |
| `unidadMedidaCodigoInterno` | string | No | 1–20 chars; must match the emitter's own unit-of-measure catalog. |
| `cantidadProductoServicio` | number | Yes | Quantity in the internal unit of measure. |
| `fechaFabricacion` | string (`date`, `YYYY-MM-DD`) | No | Manufacture date. |
| `fechaCaducidad` | string (`date`, `YYYY-MM-DD`) | No | Expiry date. |
| `codigoItemCodificacionPanamenaAbreviada` | integer | No | ≤ 99. Abbreviated Panamanian goods/services code. |
| `codigoItemCodificacionPanamena` | integer | Conditional | Required when selling to Public Administration (`tipoReceptorFe` = `3`). |
| `unidadMedidaCodificacionPanamena` | string | No | 1–30 chars. |
| `informacionInteresEmisor` | string | No | ≤ 5000 characters. |
| `grupoPrecios` | Object | Yes | Item pricing (`precioUnitarioTransferencia`, `precioItem`, `precioAcarreo`, `sumaPrecioItem`, etc). |
| `grupoITBMS` | Object | Yes | `tasaITBMSAplicable` (`01`=7%, `02`=10%, `03`=15%, `00`=0%), `montoITBMS`. |
| `grupoISC` | Object | No | Only if the item is subject to ISC. |
| `grupoOtrasTasasImpuesto` | Array of Objects | No | Only if the item carries additional taxes/fees. |

### `totales`

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `tiempoPago` | integer | Yes | `1` Contado, `2` Crédito/Plazo, `3` Mixto. |
| `grupoDescuentosBonificaciones` | Array of Objects | No | Discounts/bonifications applied to the total. |
| `grupoFormasPago` | Array of Objects | Yes | `formaPago`, `valorCuotaPagada`, etc. |
| `grupoRetencionesFactura` | Object | No | Only when withholdings apply. |
| `grupoInformacionPago` | Array of Objects | Conditional | Required when `tiempoPago` is `2` or `3` (Crédito/Mixto). |
| `grupoTotalTasas` | Array of Objects | No | |
| `totalNeto` | number | No | Sum of pre-tax prices. Calculated by the system if omitted. |
| `totalITBMS` | number | No | Calculated by the system if omitted. |
| `totalISC` | number | No | Calculated by the system if omitted. |
| `totalGravado` | number | No | Calculated by the system if omitted. |
| `totalDescuento` | number | No | Sum of discounts/bonifications. Calculated if omitted. |
| `totalAcarreo` | number | No | Freight charged in the total price (mutually exclusive with per-item `precioAcarreo`). |
| `totalSeguro` | number | No | Insurance charged in the total price (mutually exclusive with per-item `precioSeguro`). |
| `totalOtrosGastos` | number | No | ≥ 0. |
| `valorTotalFactura` | number | Yes | `totalTodosItems + totalAcarreo + totalSeguro - totalDescuento`. Calculated by the system if omitted. |
| `sumaValoresRecibidos` | number | No | Sum of `valorCuotaPagada` across `grupoFormasPago`. Calculated if omitted. |
| `vuelto` | number | No | `sumaValoresRecibidos - valorTotalFactura`. Calculated if omitted. |
| `numeroTotalItems` | number | No | Item count. |
| `totalTodosItems` | number | No | Sum of `sumaPrecioItem` across all `listaItems`. |

| Field | Type | Description |
|-------|------|-------------|

| `requestTime` | Number | Processing time, in seconds |
| `autorizada` | Boolean | `true` if the DGI/PAC authorized the transaction |
| `protocoloAutorizacion` | String | Authorization protocol assigned by the PAC |

| `xml` | String | Returned only if `xml=true` was sent |

## Listing invoices

```ruby
client.invoices.list(
  date_from: "2026-01-01",  # DateFrom
  date_to:   "2026-12-31",  # DateTo
  ruc:       "8-123-4567",  # Ruc
  name:      "Acme Corp",   # Name — receiver name/razón social
  status:    ["authorized"],# Status — one or more of: pending, authorized, canceled, error
  page:      1,             # Page
  page_size: 50,            # PageSize
  environment: nil,         # Environment — deprecated by the API, accepted but discouraged
  locale:    "es-PA"        # Accept-Language (required, default es-PA)
)
```

Only the filters above are supported by the real endpoint. Earlier versions of this gem also
accepted `document_number`, `billing_point`, `branch_office_code`, `document_type_codes`,
`cufe`, and `created_by` — none of these exist in the official API, so they have been removed;
passing them is silently ignored rather than sent as meaningless query params.

Response shape (`InvoicePaginatedResponse`):

| Field | Type | Description |
|-------|------|-------------|
| `data` | Array of `Transaction` | See below |
| `currentPage` | Integer | |
| `pageCount` | Integer | |
| `pageSize` | Integer | |
| `rowCount` | Integer | |
| `firstRowOnPage` | Integer | |
| `lastRowOnPage` | Integer | |

`Transaction` fields: `id` (uuid), `issueDate` (date-time), `validationDate` (date-time or null),
`rucReceiver` (string or null), `nameReceiver` (string or null), `totalAmount` (double),
`totalAmounttITBMS` (double), `status` (`pending` | `authorized` | `canceled` | `error`).

## Credit notes and debit notes

Panama's DGI defines several credit/debit note document types. The gem provides a helper for
each so you do not have to set `tipoDocumento` and build the reference structure manually.

### Document type codes

| Code | Method | Description |
|------|--------|-------------|
| `"04"` | `create_credit_note` | Nota de Crédito referente a una o varias FE |
| `"05"` | `create_debit_note` | Nota de Débito referente a una o varias FE |
| `"06"` | `create_generic_credit_note` | Nota de Crédito genérica |
| `"07"` | `create_generic_debit_note` | Nota de Débito genérica |

All helpers accept the same keyword options as `create` (`include_qr:`, `include_xml:`, `locale:`).

### Tipos 04 / 05 — referenced notes

These must point back to the CUFE of the original invoice (`documentosFiscalesReferenciados`,
DGI Ficha Técnica v1.10 field B606).

```ruby
client.invoices.create_credit_note(
  base_payload,
  referenced_cufe: "CUFE-OF-ORIGINAL-INVOICE",
  referenced_date: "2026-06-01",   # YYYY-MM-DD issue date of original FE
  include_qr: true
)

client.invoices.create_debit_note(
  base_payload,
  referenced_cufe: "CUFE-OF-ORIGINAL-INVOICE",
  referenced_date: "2026-06-01"
)
```

The gem builds the nested `documentosFiscalesReferenciados` structure automatically:

```json
{
  "datosGenerales": {
    "tipoDocumento": "04",
    "documentosFiscalesReferenciados": [
      {
        "fechaEmisionDocumentoReferenciado": "2026-06-01",
        "informacionReferencia": {
          "informacionReferencia": {
            "cufeReferenciado": "CUFE-OF-ORIGINAL-INVOICE"
          }
        }
      }
    ]
  }
}
```

Any other keys already present in `datosGenerales` (emitter, receptor, dates, etc.) are preserved.
`tipoDocumento` in the base payload is overridden by the helper.

### Tipos 06 / 07 — generic notes

Generic credit/debit notes do not reference a specific original FE, so no CUFE is needed.

```ruby
client.invoices.create_generic_credit_note(base_payload)
client.invoices.create_generic_debit_note(base_payload, include_xml: true)
```

The helpers set `tipoDocumento` to `"06"` and `"07"` respectively, leaving the rest of the
payload untouched.

## Other methods

Every method below now accepts a `locale:` keyword (default `"es-PA"`) and sends it as
`Accept-Language`, which the official API marks **required** on all of these endpoints.

| Method | Endpoint | Notes |
|--------|----------|-------|
| `create_from_xml(xml_string, locale:)` | `POST /api/v1/Invoices/CreateInvoiceFromXml` | Sends `Content-Type: application/xml`. |
| `authorization(cufe, locale:)` | `GET /api/v1/Invoices/Authorization/{cufe}` | `cufe` is a fixed 66-character string. |
| `authorization_admin(cufe, locale:)` | `GET /api/v1/Invoices/AuthorizationAdmin/{cufe}` | Admin variant of the above. |
| `qr_image(cufe, locale:)` | `GET /api/v1/Invoices/GetQrImage/{cufe}` | `cufe` is 66 characters. |
| `xml_from_dgi(cufe, locale:)` | `GET /api/v1/Invoices/GetXmlFromDGI/{cufe}` | The gem always sends `Accept: application/xml`; without it the API replies with JSON (`events` + `xmlRaw`) instead of raw XML. |
| `taxpayer_response(invoice_id, locale:)` | `GET /api/v1/Invoices/GetTaxpayerInvoiceResponse/{invoiceId}` | "Consulta del detalle de una factura de un contribuyente (CLIENTE)" — `invoiceId` is a UUID. |
| `find(cufe_id, locale:)` | `GET /api/v1/Invoices/id/{cufeId}` | |
| `cafe_file(cufe_id, locale:)` | `GET /api/v1/Invoices/{cufeId}/cafe-file` — raw PDF bytes | `cufeId` is a UUID. |
| `xml_file(cufe_id, locale:)` | `GET /api/v1/Invoices/{cufeId}/xml-file` — raw XML bytes | `cufeId` is a UUID. |
| `html_cafe(cufe_id, cafe_format:, locale:)` | `GET /api/v1/Invoices/{cufeId}/html-cafe` | `cafe_format` is optional: `"user_default"`, `"eighty_mm"`, or `"eighty_mm_lite"` (thermal-printer output). |

`mail_to` (`POST /api/v1/Invoices/{invoiceId}/mailto`) was removed — it wasn't covered by any of
the official reference docs used to write this file, so its request/response shape was never
verified against the live API.
